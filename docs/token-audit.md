# Token audit — long tail

Source of truth: `tools/token-report.txt` (generated by `tools/extract-tokens.mjs`
against the two `.dc.html` prototypes). Rule: a value with **3 or more** uses is
a token. Everything below that threshold is reviewed individually against the
markup and gets one of three decisions:

- **tokenizar** — kept as its own `--nc-*` custom property because it plays a
  semantically distinct role (a different UI state, a paired background/border,
  a gradient stop, etc.).
- **ajustar** — folded into the nearest existing token because the difference
  from that token is small enough to read as prototype drift, not intent.
- **excepción** — left out of `src/tokens/` entirely: a one-off decorative
  value (illustration/mascot accents) with no reusable UI role and no close
  existing token to fold into.

This table covers every one of the 72 distinct colors in the report that is
**not** a literal value in `src/tokens/_colors.scss`'s original (Task 3, Step 3)
block — 33 values in total. Three of them (`#6e7e9e`, `#d6dde9`, `#e4eaf5`)
technically clear the 3+ "is a token" bar but were not present in that block;
they are audited here too so that no value from the report is left without a
written decision, and are now tokenized in the "audit additions" `:root` block
appended to `_colors.scss`. RGB-distance figures below are Euclidean distance
between the two colors' RGB triplets (0–441 range); the plan's own worked
example (`#2e4472` → `--nc-navy-mid`) sits at 25.6, used here as the reference
point for "close enough to read as drift."

# Task 4 — typography, radius and gap tail

Same rule as above (3+ uses is a token, otherwise tokenizar / ajustar / excepción,
decided against the `.dc.html` markup, never silently rounded), applied to the
`fontSize`, `radius` and `gap` groups from `tools/token-report.txt`.

**Correction (post-review).** An earlier version of this section folded nine
3+-use font sizes (`14px`, `15px`, `12px`, `11px`, `22px`, `20px`, `18px`,
`25px`, `27px`) into a nearby existing token on the theory that a ≤0.5–1px
gap is sub-pixel and invisible once text is anti-aliased. That reasoning does
not apply here: the rule is **3+ uses is a token, full stop** — this
extraction never consolidates a value into a token for looking "close enough"
aesthetically. A sub-pixel gap between two font sizes still changes computed
line-height and line-break points, and 14px vs. 14.5px does that in 61
places. Whether two close sizes are the same intentional value or prototype
carelessness is a design call, not an extraction call: tokenizing both is
reversible, silently rounding one into the other is not. All nine values
below are corrected to **tokenizar**. Where a pair still reads as likely
carelessness, it is flagged instead of merged — see "Candidatos a
consolidación" after the table.

**Plan gap found (same pattern as the 3 colors in Task 3).** The literal
`_typography.scss` block from Step 3 only captures 12 of the 31 distinct font
sizes in the report. Unlike the color case, this is not 3 stray values: **14
of the 19 missing sizes clear the 3+ "is a token" threshold on their own**
(14px alone has 61 uses — more than several sizes that *are* in the block).
Radius has no such gap: its only missing values are exactly the 4 the plan's
own Step 7 named (`5px`, `8px`, `13px`, `20px`). Gap has a smaller version of
the same gap: 5 values (`9px`, `7px`, `11px`, `5px`, `28px`) clear 3+ uses
without being named anywhere in the plan. All of these are audited below and,
where the decision is "tokenizar", added to the "audit additions" blocks in
`_typography.scss` / `_space.scss`.
